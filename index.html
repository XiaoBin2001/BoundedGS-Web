BoundedGS: Memory-Efficient High-Resolution Training
for 3D Gaussian Splatting

Xiaobin Deng Changyu Diao* Min Li Duanqing Xu*

Zhejiang University

* Corresponding authors.

Paper ↗arXiv ↗GitHub ↗Cite

Keep full-view supervision. Control temporary memory at high resolution.

Same starting model. Higher image resolution. Starting from the same Bicycle model with 5.99 million Gaussians, we keep the views and field of view unchanged and increase image width from 1K to 16K. We compare the temporary working set, training computation time, and L1 loss.

01 / Problem & insight

Collect gradients from the full view.
Release local caches along the way.

Higher resolution brings more pixels and more intersections between Gaussians and image tiles. Rasterization caches coexist with projection and gradient state, together creating the training memory peak.

Complete gradients do not require every cache at once.

Gaussian parameters stay fixed within a view. Once a region finishes rasterization, loss, and backward computation, its gradient contribution can be accumulated and its local caches released before the next region runs.

Partition by workload, not just image area.

Two regions with the same area can contain very different numbers of Gaussian intersections. BoundedGS estimates load from intersections, pixels, and buffer layout, using smaller regions where the workload is dense and larger ones where it is sparse.

The regions still cover the entire image and share one camera and global model. Accumulate gradients across the whole view, then update the parameters once.

02 / Method

Release local caches sooner.
Then address projection and gradient peaks.

Figure 3 follows one sequence of changes: A executes the full image; B separates the two backward stages; C bounds local rasterization; D and E compact projection and gradients; F explores a smaller budget and more groups.

A → B

Separate backward stages to release caches sooner

First complete rasterization backward and collect gradients of projected attributes, then run projection backward. Rasterization caches can leave memory before later gradient state grows.

B → C

Bound local rasterization with a workload budget

Split the image into leaves, each completing forward, loss, and backward computation. Regions that exceed the budget are subdivided further. A layout can be cached per camera, with its current load checked before every execution.

C → D → E

Keep detailed state for candidate Gaussians

As local caches shrink, full-model projection and gradients become the next bottleneck. Candidate-indexed projection and compact gradients retain detailed state only for Gaussians that may contribute to the current view.

Carry the same principle into full training.

More projection groups and a smaller leaf budget (F) can reduce the working set further, with more execution overhead. Beyond rendering, CPU-assisted structure rebuilding and bounded image supply help control resource use throughout training.

384 MiB is the local rasterization budget, not a limit on the whole training process. Local SSIM windows differ from full-image SSIM at region boundaries; final quality is evaluated on complete images.

Why not just split the image into uniform blocks?

Figures 5 / 6

Splitting into blocks can also save memory. The key questions are how to choose block size, and how much work to repeat for each block. We first give fixed blocks compact projection and gradients too, then compare partitioning strategies and the cost of per-block updates.

Figure 5 · Fixed pixels vs. workload-based regions

With compact state in both paths, Auto Leaf still improves efficiency.

Use the same Bicycle model with 5.99 million Gaussians and increase resolution from 2K to 16K. All three paths separate stages and compact projection and gradients. A/B use blocks 2K pixels wide; C partitions by a 384 MiB workload budget.

B → C: one update per view, a better fit to local load. A fixed-area block can still contain dense Gaussian intersections. Auto Leaf adjusts region size to the load, keeping the working set near 1.07 GiB. At 16K, time falls from 49.3 seconds with fixed blocks to 35.7 seconds.

A → D: updating every block makes memory savings expensive. At 16K, an 8 × 8 grid means 64 parameter updates per view, along with repeated screening, projection, and gradient construction. This pass takes 149.4 seconds.

Figure 5 takeaway: local workload sets cache size; a single update after the full view avoids the repeated work of per-block updates.

Figure 6 · The cost of finer fixed grids

Finer grids keep cutting memory, but take longer.

Switch to a Bicycle model with 11.98 million Gaussians and compare 1 × 1, 2 × 2, and 4 × 4 grids, updating each block independently. The top row repeats full projection; the bottom row already uses stage separation, candidate projection, and compact gradients.

Compact state does not remove repeated work. The 2 × 2 and 4 × 4 grids perform 4 and 16 parameter updates per view. In the bottom row, their times rise from 21.84 to 65.36 seconds.

Compare memory and time against Auto Leaf on the same model. Auto Leaf uses 1.572 GiB and 11.57 seconds. Compact 4 × 4 reaches 0.848 GiB, saving another 0.724 GiB of temporary memory, but takes about 5.65 times as long.

Figure 6 takeaway: smaller fixed blocks can reach a lower peak; Auto Leaf offers a better memory–time trade-off by avoiding repeated computation.
